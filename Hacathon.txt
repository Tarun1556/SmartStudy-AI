You are the lead software architect, senior full-stack engineer,
AI engineer and product designer for this hackathon project.

The attached SRS is the primary product specification and source
of truth.

Your job is to build a complete, polished, deployable MVP based
on that SRS.

===========================================================
PROJECT GOAL
===========================================================

Build an AI-powered web application that transforms scattered
semester lecture material into a structured, evidence-backed
study system.

The application must support:

- audio/video lecture uploads
- transcript input
- PDF/PPTX upload
- text extraction
- speech-to-text
- structured lecture notes
- topic extraction
- cross-lecture topic merging
- frequency/coverage analysis
- searchable archive
- PDF study-guide export

The application should also include selected stretch features
that create strong differentiation:

1. Semester Knowledge Map
2. Evidence-backed notes
3. Topic Coverage Timeline
4. Grounded "Ask Your Notes" Q&A
5. Auto-generated practice questions / flashcards

Do NOT turn this into a generic AI chatbot.

The core product identity is:

SCATTERED LECTURE MATERIAL
        ↓
UNDERSTANDING
        ↓
CROSS-LECTURE CONNECTIONS
        ↓
EVIDENCE-BACKED KNOWLEDGE
        ↓
PERSONALIZED STUDY GUIDE

===========================================================
PRODUCT POSITIONING
===========================================================

The application is a general student product and should NOT
assume a specific college.

Students from different colleges, departments and domains can
use it.

Implement user accounts so each student's courses, lectures,
notes and study history are private.

However, the public landing page MUST provide:

"Try Demo"

This opens a pre-seeded read-only demo workspace containing
5-6 processed lectures.

The judge should be able to experience the product without
creating an account.

Actual user uploads and personal data require authentication.

Do NOT implement college-specific SSO, college IDs, sections,
branches or institutional administration in the MVP.

===========================================================
LECTURE INGESTION PIPELINE
===========================================================

A lecture may contain:

1. audio/video
2. PDF
3. PPTX
4. pasted transcript

Create an ingestion pipeline:

UPLOAD
 ↓
VALIDATE
 ↓
EXTRACT / TRANSCRIBE
 ↓
NORMALIZE TEXT
 ↓
CHUNK
 ↓
GENERATE STRUCTURED NOTES
 ↓
EXTRACT TOPICS
 ↓
GENERATE EMBEDDINGS
 ↓
MERGE WITH EXISTING COURSE TOPICS
 ↓
UPDATE STUDY GUIDE
 ↓
INDEX FOR SEARCH

Long transcripts MUST use chunking / map-reduce rather than
sending the entire lecture directly to the LLM.

Every processing operation must produce a visible status.

===========================================================
TOPIC INTELLIGENCE
===========================================================

This is the heart of the application.

For every lecture:

1. extract candidate topics
2. normalize topic names
3. generate embeddings
4. compare against existing course topics
5. merge semantically similar concepts
6. create a canonical topic label
7. create topic mentions
8. preserve source evidence

Example:

"BST"
"Binary Search Tree"
"Binary Search Trees"

should resolve into one concept where appropriate.

Do not rely only on exact string matching.

Use embeddings + similarity threshold.

Allow threshold to be configured through settings.

===========================================================
COVERAGE SCORE
===========================================================

Do NOT claim:

"This topic will appear on the exam."

Instead use transparent language:

- Frequently Covered
- Revisited Across Lectures
- High Course Coverage

Calculate a simple explainable coverage score from factors
such as:

- number of distinct lectures mentioning the topic
- number of source types containing the topic
- recurrence across the lecture sequence
- number of supporting evidence segments

Expose the underlying evidence.
